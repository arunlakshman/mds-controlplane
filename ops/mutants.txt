# Mutants for make mutants (see ops/tools/mutate).
#
# A mutant is one exact text replacement in one real source file. The tool applies
# it to a copy of the tree and runs the test command. The mutant is killed when
# the command fails. If a mutant survives, or its old text is not in the file
# exactly once, make mutants fails.
#
#   mutant NAME            a short name, used in the output and for -only
#   file PATH              the source file, from the repository root
#   run COMMAND            the narrowest test command that kills it (no shell). A
#                          conformance test runs with no seed: test/conformance Run
#                          makes more rounds of checks until every answer that an
#                          operation aims at was seen, so a kill does not depend on
#                          luck. A fixed seed would turn that off.
#   @@ old                 the old text, exactly, one or more lines
#   @@ new                 the new text
#   @@ end
#
# The bugs that need a broken environment, not broken code, stay as test doubles:
# a crash that loses answered writes (TestDoubleCrashLosesAnsweredWrites) and no
# data after a failure (TestDoubleNoDataAfterFailure), both in
# test/conformance/doubles_test.go, and the simulator bugs log-overwrite and
# claim-always-wins in the fake log.
#
# The conformance mutants run TestMetadataMemory: it is the target with the most
# checks (the Pebble one runs fewer, and the wire has no group operations).

		assigned, code := replay(rec, dig, operation)
